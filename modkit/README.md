# modkit

Build RISC OS **relocatable modules** with the GCC 16 EABI cross compiler (and, for C modules, with the native `Gcc16` on RISC OS), with no UnixLib or Shared C Library, with the commands of GCCSDK 4.7.4 (`gcc -mmodule`, `cmunge`; since 16.2.0-14). Experimental, for small and medium C and C++ modules (a C library of about 590 functions of its own, with `stdio` files, floating point and sockets, and C++ without exceptions, RTTI, streams or threads: [what can and cannot be built](../docs/MODULES.md#what-can-be-built-today-and-what-cannot)). See [docs/MODULES.md](../docs/MODULES.md) for what it is, how to build the examples (`examples/tickmod`, `examples/cxxmod`), what was proven on hardware, and the limits. **To move a module from GCCSDK 4.7.4 see [docs/PORTING-FROM-4.7.4.md](../docs/PORTING-FROM-4.7.4.md)** (why move, and who should not). OSLib for modules is in [docs/OSLIB.md](../docs/OSLIB.md), and what the kit builds of the RISC OS Open sources in [docs/OS-MODULES.md](../docs/OS-MODULES.md).

| Folder | |
|---|---|
| `src/` | the C programs `cmunge`, `modreloc` and `mkoslib` (one source for Linux and for RISC OS: these are the tools that the tool chain and the native package ship). For `-p` and `-o`, `cmunge` starts a C compiler: the one named by the environment variable `CMUNGE_CC`, else `arm-riscos-gnueabihf-gcc` next to it or on the path; its temporary files go to `TMPDIR`, or `/tmp` |
| `bin/` | the first versions of the three tools, in Python (`cmunge`, `mkmodhdr.py` for the CMHG file to module header and veneers, `mkoslib.py`, `modreloc.py`), kept for the tests that compare the C ones with them; also `asasm-fix.sh` (installed as `arm-riscos-gnueabihf-asasm-fix`: it makes the objects of GCCSDK's `asasm` linkable), `mklibgcc.sh` (makes `libgcc-mod.a` and `libstdcxx-mod.a`; `install-modkit.sh` runs it), `mkoslib-lib.sh` (makes `libOSLib32.a` from your own copy of OSLib's headers) and `swis-extra.txt` |
| `bin/mkswis.py` | makes `include/swisnums.h`, the SWI numbers, from the assembler headers of the RISC OS Open sources (not needed to build or use the kit: the result is in the repository) |
| `lib/` | the C library of the kit (one source per group of functions, built with each function in a section of its own, so that the link drops what a module does not call), integer division, the SWI veneer, the linker script, and the SWI and service numbers read from the RISC OS sources |
| `include/`, `include-cxx/` | the headers of the kit's C library (about 50: the socket, `wchar`, `complex`, `iconv` and `fenv` headers among them), and the kit's `<cmath>`, `<math.h>` and `bits/` headers for C++ modules |
| `module.mk` | make rules to include from a module's Makefile (needs GNU make 4.3 or later). The variables are `MODULE`, `CMHG`, `SRCS` and, when you need them, `OSLIB_FUNCS`, `BIN` (the tool chain's `bin` folder: the default is the author's layout, so pass it from a checkout), `OSLIB`, `BUILD`, `EXTRA_CFLAGS`, `EXTRA_CXXFLAGS`, `CXXSTD`, `CMUNGE`, `MKOSLIB` and `MODRELOC`; there is a `clean` target. The compile flags include `-ffunction-sections -fdata-sections`, and `-mmodule` passes `--gc-sections` to the linker |
| `examples/tickmod`, `examples/cxxmod` | a module that claims `TickerV` and uses callbacks, and a C++ module |
| `NOTES-fp.md` | notes on floating point in modules |
| `tests/` | host simulations of the module's machine code on an ARM interpreter, against a model of the RISC OS kernel; the library test against glibc (`libtest/`); the tool tests (`test-ctools.py`, `test-gccsdk-modules.py`, `test-gccsdk-examples.py`); and the sources of the runs on a Raspberry Pi: `hwpack/` (the modules and programs), `sockets/`, `oslib/`, `desklib/`, `flexsf/`, `rufl/`, `nsbench/`, `cxx/` (the C++ subset). [docs/TESTING.md](../docs/TESTING.md) says what each test is for |

The tool chain's `recipe/gcc-16.2.0-riscos/scripts/install-modkit.sh` puts the kit into the cross compiler: `libmodkit.a` (a linker script that names `libmodkit-core.a`, `libgcc-mod.a` and `libstdcxx-mod.a`), the linker script of a module, the headers, and `cmunge`, `arm-riscos-gnueabihf-modreloc`, `-mkoslib` and `-asasm-fix` in `bin/`, and a copy of the library sources, the headers and `module.mk` in `share/riscos-modkit/`. It builds `libOSLib32.a` only when `OSLIB` names a folder that has OSLib's headers. It does not install the Python tools, the tests or the examples.
