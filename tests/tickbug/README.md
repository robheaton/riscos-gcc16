# tickbug: does UnixLib's thread ticker fire into other tasks?

When a program has more than one thread, UnixLib starts a system-wide `OS_CallEvery` ticker that switches threads. Until the runtime 16.2.0-15 (fix level 17) the ticker's routines ran from the program's own memory, and the ticker fires whichever task is paged in: **a program linked statically** (`libunixlib.a`) that made a thread **before `Wimp_Initialise`** (as SDL programs do: the Wimp filters that would stop the ticker are not registered yet) made every other task abort with `Internal error: abort on data transfer at &...` or `abort on instruction fetch`, and then locked the machine. It was found with a statically linked picture viewer reported by a user, and reproduced with this program on a Raspberry Pi Compute Module 4 (RISC OS 5.30). The fix is the thread ticker of Andrew Youll's [riscos-unixlib](https://github.com/adyoull/riscos-unixlib) (see [RUNTIME.md](../../docs/RUNTIME.md)).

`tickerbug.c` is a small Wimp task: `tickerbug early|late LOGFILE`. It puts an icon on the icon bar, polls with `Wimp_PollIdle` (it sleeps 0.5 s at a time, so other tasks run while it is paged out), writes a line a second to `LOGFILE`, and ends by itself after 120 seconds (`SURVIVED 120 s` in the log) or when its icon is clicked.

* `early`: the thread is created before `Wimp_Initialise`. Linked statically with a library without the fix, other tasks abort within seconds. Linked dynamically it was fine (the code is in the shared library area, which every task can see).
* `late`: the thread is created after `Wimp_Initialise`, when the filters can be registered: the control, fine in every variant.

`build-tickbug.sh OUTDIR [TOOLCHAIN]` builds both links. Make an application folder for each (`!Run` with `WimpSlot -min 4096k -max 4096k` and `Run <Obey$Dir>.tb early <Wimp$ScrapDir>.TickLog`), start it from the desktop **with a few other tasks open** (MiniTime, Alarm ...), and watch. **Save your work first: with a library that has the bug the machine can lock.** With the fixed library setting `UnixLib$TickerStats` to a file name makes the program append a line of counters when it exits: `ticks` (timer ticks), `foreign` (ticks that found another task paged in and did nothing), `via=RMA` or `via=module` (where the ticker routines ran from).

Results of 14 October 2026: 16.2.0-23, static, early: another task aborted at once, then an endless `abort on data transfer` on the screen; static, late: fine; dynamic, early: fine. With the fixed library (fix level 17), static, early: 120 s, 6025 ticks, all of them found another task paged in, no abort, `via=RMA`; and the same with the PThreadTicker module loaded, `via=module`.
