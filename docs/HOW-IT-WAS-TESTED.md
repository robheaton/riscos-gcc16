# How the 32-bit tool chain was tested

This page is about the 32-bit tool chain of the [main README](../README.md). The 64-bit preview has its own test notes in [RISCOS64.md](RISCOS64.md) and [USERLAND64.md](USERLAND64.md).

On a Raspberry Pi Compute Module 4 (Cortex-A72) with RISC OS 5.30, ARMEABISupport 1.08 and Shared Object Manager 3.04. The compiler differs from that of 16.2.0-16 only in two options of its driver (16.2.0-20), in how the cross compiler reads `#include "Prefix:Name.h"` (16.2.0-21) in libgcov's profile directories (16.2.0-22) and, in 16.2.0-23, in one option of the linker that `-mmodule` passes (`--gc-sections`), and in 16.2.0-24, in the thread ticker of UnixLib (the runtime 16.2.0-15, fix level 17); UnixLib has seven more error codes (16.2.0-22, runtime 16.2.0-14, fix level 16) and the rest of the runtime packages is as in 16.2.0-16; 16.2.0-17 to -23 changed the module kit; they passed all of the following on that machine (what was run with the packages of 16.2.0-24 is in the last paragraph of this section):

* the C regression suite `rotest` (34,541 checks: integers, 64-bit arithmetic, floating point, conversions, varargs, `alloca`, `setjmp`, unwinding, atomics, PIC data, C23) and the C++ suite `cxxtest` (139 checks), built both
  by the cross compiler and by the native compiler (the native compiler's objects are byte-identical to the cross compiler's);
* the thread tests (`std::thread`, `std::async`, `call_once`, timed waits, `thread_local`), the Fortran suite (122 + 54 + 26 + 30 + 9 checks, plus an error-exit test) and a dynamic-library suite;
* the native compiler building real software: zlib 1.3.1 (also with `-flto`) and GNU make 4.4.1 itself;
* the runtime's own checks: 48 library checks, 23 memory-guard checks, 12 process-exit checks, six heap-growth scenarios of `vfork` + `exec` children, a table of 15,066 `sscanf` cases, the `.fini_array` (destructors), `getrlimit (RLIMIT_STACK)`, 20 POSIX semaphore checks and the `.gcda` files of coverage and profile programs (16.2.0-12), and, new in 16.2.0-13, the profiler behind `-pg`;
* coverage: programs built by the cross compiler wrote their `.gcda` files on the Pi and the Linux `gcov` read them; the native compiler did the same (`--coverage`), the native `gcov` read the file and wrote the annotated source (80.00% of 15 lines, every line count checked by a small program), and `-fprofile-use` found the profile of an instrumented run (checks 9 and 10 of the self-test);
* gprof: a program built by the cross compiler with `-pg` ran on the Pi in three runs of 6 seconds and wrote a valid `gmon.out` each time: the call counts equal the program's own counters exactly, 237 to 240 samples at 50 a second, and the native `gprof` and the Linux `gprof` print the same profile; the native compiler did the same (`gcc -O1 -pg`, a run, `gprof`): a program that calls two functions ten times each gets exactly 10 calls for each in the report (check 11 of the self-test);
* throwback: the native assembler and the native linker send their errors to StrongED (a throwback window with the entries; a double click opens the source at the line); the compilers' throwback was tested before (16.2.0-8);
* modules (16.2.0-14): the self-test builds a small module on the Pi with `cmunge` and `gcc -mmodule`, loads it, runs its command and removes it; a network module of 800 lines of C (sockets, files and OS calls through 23 OSLib veneers) was built on the Pi in 3 seconds by the commands of a GCCSDK 4.7.4 makefile, is **byte for byte the module that the Linux cross compiler makes from the same source**, and passed 39 network checks on the machine (a soak of 300 commands, files up to 500 KB, a client that vanishes). The same test with the packages of 16.2.0-15 (the new kit): 4 seconds, byte for byte the module that the Linux tarball makes, and the same 39 network checks.
* the module kit of 16.2.0-15 (run on the Pi on 2026-10-07, before the release): the kit's C library against glibc on the real file system (every compared section equal, the `stdio` section of 21,068 results among them; also the heap, `setjmp`, `getenv` and the real SWIs), a module run as a program with `module-is-runnable` (`*RMRun` with arguments, the exit codes), international help, `add-syntax:`, a SWI prefix that differs from the title, a generic veneer in SVC mode, in USER mode and at interrupt time, `exit` in a command, and the keyboard and screen streams of `stdio`.
* three modules of the RISC OS Open sources built with the module kit of 16.2.0-16 (run on the Pi on 2026-10-08, before the release): Squash (with its assembler), MimeMap and DrawFile, loaded over the ROM's own modules, gave the same results as the ROM's in everything the same test program compares: 545 checks on each side, 9,820 lines of results compared and none different, the ROM's modules started again afterwards, and DrawFile painted 13 cases (8 Draw files) into a sprite with the same pixel count, bounding box and checksum ([docs/OS-MODULES.md](docs/OS-MODULES.md#compared-with-the-rom)). Running the same program on an interpreter beforehand had found two faults of `cmunge` in 16.2.0-14 and 16.2.0-15, fixed in 16.2.0-16 ([CHANGELOG](../CHANGELOG.md));
* floating point, `math.h` and C++ in modules, built with the module kit of 16.2.0-17 (run on the Pi on 2026-10-09 and 2026-10-10, before the release): a module (`FpSvc`) that formats and reads floating point numbers, does arithmetic and calls `math.h` in SVC mode and in a generic veneer at interrupt time gave the answers that glibc and Python give (892 + 791 + 10 checks, and the same bits as the host in 100 interrupt-time calls); two modules written in C++ ran their static constructors and destructors in the right order, `new` and `delete`, virtual functions, and `std::string`, `std::vector`, `std::map`, `std::set`, `std::list`, `std::unordered_map`, smart pointers and `std::function`, printing the same text as the host (33 lines, 0 differ); and the kit's C library as a module (`LibTest`) gave glibc's results in every compared section, 318,000 more results for floating point among them ([docs/MODULES.md](docs/MODULES.md#c-in-modules)).
* the CMHG options of 16.2.0-18 and the faults of the kit that it fixes (run on the Pi on 2026-10-10, before the release): a test module (`CmhgT`, 65 checks) with a SWI function of its own, `handler:` and `no-handler:` commands, generic veneers with `private-word:` and `carry-capable:` and vector veneers with `error-capable:`, all with real flags; two modules with `swi-decoding-code:` (the kernel asks the code for names and numbers; the first run found two faults, fixed); and a module (`KitFix`) that checks that an undefined weak reference and an absolute symbol stay 0 ([docs/MODULES.md](MODULES.md), [docs/OS-MODULES.md](docs/OS-MODULES.md#new-in-1620-18)).
* BSD sockets and the OSLib veneers in modules, built with the module kit of 16.2.0-19 (run on the Pi on 2026-10-10, before the release): a module (`SockHw`) that does TCP and UDP on the loopback address (non-blocking `connect`, `select`, `accept` with the peer's address, `shutdown`, `EBADF`, `EWOULDBLOCK`, `ECONNREFUSED`), resolves `localhost` through the Resolver, and calls the X and non-X OSLib functions of `libOSLib32.a`: 53 checks, 0 failed; an echo server in the same module answered a client on another machine (three messages and the end of file); a non-X OSLib error ended the whole command line, as a non-X SWI error does; and `__modlib_stack_left ()` read 32,172 bytes at the top of a command and fell with the depth of the recursion. A private stack for modules was tried in the same session: the Task window aborted ([docs/MODULES.md](docs/MODULES.md#sockets)).
* CMunge's error blocks and the new C library functions, built with the module kit of 16.2.0-20 (run on the Pi on 2026-10-10, before the release): a module (`ErrMod`) with `error-chunk-base-number:` and `error-identifiers:` returned four errors that came back with their numbers (&838000, &838001, &838010, &838002) and messages; 20 checks, 0 failed (`system ()`, the `_kernel_` functions and the wide character functions among them); an unknown command run from the module gave error &D6; `_kernel_raise_error` ended the whole command line, as the kernel's error handler does ([docs/MODULES.md](MODULES.md)).
* The string, environment, time, `getline`, `fnmatch`, `err` and `aligned_alloc` functions of the C library (the names that GCCSDK 4.7.4's module library had), run on the Pi on 2026-10-11, before the release: `LibTest`, the library run as a program, gave the same answers as glibc for 20,920 string and time results, 24,000 `fnmatch` results and 3,786 `getline` results, and passed 38 checks of the functions that need the OS (system variables, `aligned_alloc`, the clock, `realpath` on the real file systems) ([docs/MODULES.md](MODULES.md)).
* The descriptor functions of the C library (`open`, `read`, `write`, `lseek`, `fstat`, `ftruncate`, `unlink`, `utime`, `fdopen` ...), run on the Pi on 2026-10-11, before the release: 800 random sequences of `open` (every combination of flags), `write`, `read`, `lseek`, `ftruncate`, `close` and `unlink` on real files gave the same answers and the same file contents as glibc (25,024 results), and 51 further checks passed, among them the date stamps of the real file system with `utime` and `utimes` ([docs/MODULES.md](MODULES.md)).
* Sockets as file descriptors, built with the module kit before the release of 16.2.0-23 (run on the Pi on 2026-10-13): the 53 socket checks of 2026-10-10 again and 51 new ones, 0 failed (`read`, `write`, `ioctl`, `fcntl`, `select`, `dup` and `close` on sockets, the interface requests, a raw `Socket_Creat` handle turned into a descriptor); the library test, still equal to glibc's in every compared section; a copy of the network module (its 39 checks); and Sunfish, an NFS client filing system, from its unmodified source: it loads, mounts an NFS export, lists it and reads 64 KB of a file with the CRC that an independent NFS client gives (read only; [tests/sunfish](../tests/sunfish/README.md)).
* The module kit of 16.2.0-23 as released, with the linker that drops the functions that nothing calls (`pack/module69`, run on the Pi on 2026-10-13, before the release): `SockHw_Raw` 4, `SockHw_Test` 53 and `SockHw_Fds` 52 checks, 0 failed; the library test with its 30 sections equal to glibc's (`c99`, 142,966 results, and `gamma` among them) and `TOTAL fail=0`; the network module (39 checks, a transfer of 500,000 bytes, a soak of 300 commands); an echo server tested from another machine; and Sunfish, built by `tests/sunfish` (224,264 bytes), which loads, mounts the NFS export of a NAS, lists it and reads 64 KB of a file with the CRC-32 of an independent client.
* The thread ticker of UnixLib (reproduced and fixed on the Pi on 2026-10-14; [tests/tickbug](../tests/tickbug)): with the libraries of 16.2.0-23 a statically linked program with a thread made before `Wimp_Initialise` made `MiniTime` abort at once, and then an endless `abort on data transfer` filled the screen; the control (thread made after `Wimp_Initialise`) and the dynamically linked program were fine. With the thread ticker of Andrew Youll's riscos-unixlib (runtime 16.2.0-15, fix level 17) the same static program ran 120 seconds while the timer fired 6025 times into other tasks, with no abort, with the routines in the RMA block and with the `PThreadTicker` module; the control showed the Wimp filters registered for the task and called on every poll.
* the fixed SharedUnixLibrary (the optional `SharedULibFix` package 1.16-vforkfix3, since 16.2.0-14): the module has been installed on the test machine since 4 Oct 2026, the `vfork` loops that froze the machine with the stock module run without a freeze, and the regression suites pass with it; the installer's logic runs through 28 simulated scenarios; the installer itself was run on the machine (`Install` on the stock module, a reboot, `Check`, `Restore`, `Install` again, a reboot, `Check`, and an `Install` that correctly refused): all passed.

The packages of this release were installed with PackMan on that machine (14 October 2026) and checked with the self-test (`tests/selftest`: twelve checks, 33 seconds; check 12 builds, loads and runs a module with the kit of this release) and the regression run (the self-test, the runtime checks and the six suites: the same 54 `SUMMARY` lines as in the earlier releases, none failing; the six heap stages of `vfork` + `exec` children ran in the same run and left every parent intact). The thread ticker test `tests/tickbug` was run with the libraries of this release (a statically linked program with a thread made before `Wimp_Initialise`, the same dynamically linked, the control and the one with the `PThreadTicker` module): each ran 120 seconds while the timer fired 6025 times, and no task aborted; with 16.2.0-23 the static program made another task abort at once. On the machine itself the native tool chain built the network module (21,644 bytes) and the test program RomCmp (68,688 bytes), each byte for byte the module of the Linux cross compiler; the network module passed 39 network checks, and RomCmp, run against the ROM's own modules, made 545 checks with 0 failed and all 9,820 lines of its results are those of 8 October.
How the build instructions were checked for this release is at the top of [docs/BUILDING.md](BUILDING.md).
The test programs are in [tests/](../tests/) and are described in [docs/TESTING.md](TESTING.md). Only one machine was used: other ARMv7 machines should work, but have not been tried.
